Recording script

CODEMD Demo Video — Step by Step

Read the SAY lines aloud while doing the ACTION above them. Ordered most → least important, so cut from the bottom if you run short on time. Target run time: ~5–7 min narrated, or record silent and voice it over after.

Before you hit record

  • Pick a real demo repo, not a toy hello-world — you need actual functions with multiple callers so the callgraph and blast radius have something to show. A repo with 200+ files works well.
  • Pre-stage one "breaking" edit in that repo before recording: rename a function, change a parameter, or delete something that's still called elsewhere — but don't save it yet. You'll save it live in Step 3.
  • Run Generate CODEMD once beforehand off-camera so the initial callgraph build (which can take a minute or two on a big repo) doesn't sit dead in the video. You'll re-trigger a quick regenerate live instead.
  • Close unrelated panels, notifications, and any open diff/merge editors so the VS Code window is clean.
  • Bump the VS Code editor/UI zoom one notch (Ctrl+=) so text is legible once the video is compressed.
  • Recording tool: open the Snipping Tool (Windows 11) → New → switch the mode toggle to the video/record camera icon → drag the capture region around the VS Code window → red Start button. Stop from the Snipping Tool flyout or Win+Shift+R-style toolbar it shows while recording.
  • Leave a beat of silence (~1s) after each click before you start talking — makes it much easier to trim between steps in editing.

Order (most → least important)

  1. Marketplace page — the hook why someone should install this
  2. Install & first look Activity Bar → panel → auto-analyze
  3. Check Uncommitted Edits the core "aha" moment
  4. Blast Radius Report risk, ranked
  5. Check Latest Commits same check, after the fact
  6. Search the codebase find anything, fast
  7. Explore the graph Expand / Full Screen, click a node
  8. Product Feature List what this repo actually does
  9. Hook it up to your AI agent (MCP) opt-in, for power users
  10. Housekeeping & close Regenerate, Clean up, CTA

1 · Marketplace page — the hook

~25s · browser

On screen

  • Open a browser tab to the CODEMD listing on the VS Code Marketplace.
  • Scroll slowly past the headline and the impact-graph screenshot — don't read the page, just let it be visible.

Say

"If you're using Claude, Cursor, Codex, or Copilot to write code, this is CODEMD. It checks your uncommitted changes against your codebase's callgraph and tells you what's about to break — before you commit. Let's install it and see it in action."

2 · Install & first look

~30s · VS Code

Action

  • Click Install on the Marketplace page (or switch to an already-installed window to save time).
  • Click the CODEMD icon in the Activity Bar (left-hand rail).
  • Let the panel open — point out the status line: "Analyzing this workspace in the background…"

Say

"After installing, click the CODEMD icon here in the Activity Bar. On first open it automatically starts building a local callgraph of the workspace — no config, nothing sent anywhere. Once it's done, the graph shows up right here in the panel."

If the graph is already built from your off-camera run, say "and here it is" instead and cut to the finished graph.

3 · Check Uncommitted Edits

~50s · the core feature

Action

  • Switch to the editor tab with your pre-staged breaking edit and press Ctrl+S to save it on camera.
  • Click Check Uncommitted Edits in the CODEMD panel.
  • Let the change report render — hover/scroll to the risk pill (Critical/High/Medium) and the caller list on the edited symbol.
  • Click one of the listed callers to jump straight to that call site in the editor.

Say

"Say Claude just changed this function's signature — or an AI agent renamed it — while I was looking away. I hit Check Uncommitted Edits, and CODEMD shows exactly what changed, every place that still calls it, and how risky the edit is. I can click straight through to any caller instead of grepping for it myself."

This is the single most important beat in the whole video — give it the most screen time and don't rush the click-through to a caller.

4 · Blast Radius Report

~25s

Action

  • Click Blast Radius Report.
  • Scroll the ranked list of affected functions/files.

Say

"Blast Radius Report narrows that down further — it only surfaces changed functions whose callers are numerous enough to actually be risky, ranked so you know what to check first instead of reading every diff line by line."

5 · Check Latest Commits

~20s

Action

  • Click Check Latest Commits.
  • Point at one recent commit and its impact summary.

Say

"Same analysis, but for changes that are already committed — useful for reviewing a PR, or checking what an agent merged while you weren't watching."

6 · Search the codebase

~35s

Action

  • Click into the Search this codebase… box at the bottom of the panel.
  • Type a natural-language query, e.g. "What calls <function name>?" or "Where is this feature implemented?" — let the suggestion dropdown show briefly.
  • Press Search and show a result, then click one to jump to it.

Say

"You don't need to know exact function names. Ask in plain language — 'what calls this,' 'where is this feature implemented,' 'trace this request from UI to database' — and CODEMD answers from the actual callgraph, not a guess."

7 · Explore the graph

~25s

Action

  • Click Expand (or Full Screen) on the graph pane.
  • Click one interesting node and let it highlight its connections.

Say

"And the whole thing is a navigable graph — expand it, click any function, file, or route, and see exactly how it connects to the rest of the codebase."

8 · Product Feature List

~20s

Action

  • Click the + next to Product Feature List to expand it.
  • Scroll a couple of detected features.

Say

"CODEMD also infers the actual product feature list straight from your code and docs — a quick way to see what a repo does without reading the README."

9 · Hook it up to your AI agent (MCP)

~30s

Action

  • Click the + to expand the MCP usage card.
  • Click Add CODEMD MCP Server.
  • (Optional, only if time allows) Click Open Claude Code /mcp or Open Codex /mcp to show it connected.

Say

"This is opt-in, but it's the part built specifically for agents — Add CODEMD MCP Server exposes this same local index to Claude Code or Codex directly, so your agent checks what it's about to break instead of re-scanning the whole repo or just guessing."

10 · Housekeeping & close

~20s

Action

  • Point at Regenerate — mention it re-runs analysis after big changes.
  • (Skip on camera, just mention) Clean up .codemd and Stop Local Server exist for resetting/uninstalling cleanly.
  • Cut back to the Marketplace page or codemd.dev for the outro card.

Say

"That's CODEMD — install it from the VS Code Marketplace, or find the details at codemd.dev. It's a pre-release preview, so if something looks off, file an issue — I'm reading every one."
